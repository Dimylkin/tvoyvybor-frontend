# ТвойВыбор.exe — frontend и локальный запуск

Этот репозиторий содержит React/TypeScript приложение и Docker Compose. Phaser отвечает за кампус и игровые взаимодействия, React — за CampusOS и диалоги, backend хранит авторитетное состояние квестов.

## Запуск

Положите репозитории рядом в одной директории:

```text
Code/
├── tvoyvybor-backend/
└── tvoyvybor-frontend/
```

Нужны Docker Compose, Node.js (22 или новее) и Python 3.12 или новее.
Для нового окружения создайте `.env` из `.env.example` и замените JWT-секрет.
Если `.env` уже существует, сохраните его. Значения PostgreSQL и JWT должны
совпадать с настройками backend; пароль в URL должен быть URL-кодирован.
Из каталога frontend:

```sh
cp .env.example .env  # только если .env ещё нет
npm ci
docker compose up -d db
```

PostgreSQL доступен только на `127.0.0.1:5433`; его данные сохраняются в
Compose volume `postgres_data`. Порт 5432 на хосте не используется. Для
существующего стенда используйте тот же Compose project (например, добавьте
`-p open-world-campus-ui-fixes-local` ко всем командам Compose), иначе будет
создан другой volume. При первом запуске новой базы примените миграции по
инструкции backend. Значения POSTGRES_* при повторном запуске не меняют уже
инициализированную базу.

В отдельных терминалах запустите приложения:

```sh
cd ../tvoyvybor-backend && make dev-start
# в другом терминале, из tvoyvybor-frontend:
make dev-start
```

Игра: <http://127.0.0.1:5173>, API: <http://127.0.0.1:8000/docs>,
проверка БД: <http://127.0.0.1:8000/health>. Vite проксирует `/api` на
локальный backend; при необходимости адрес прокси задаётся переменной процесса
`VITE_BACKEND_PROXY`. Каждый процесс останавливается через Ctrl+C, база —
`docker compose stop db` с тем же именем проекта. Данные сохраняются.
Если порт занят, остановите только принадлежащий вам процесс; при ошибке 503
проверьте контейнер, URL и учётные данные базы. Если зависимости отсутствуют,
повторите `npm ci` или настройку backend из его README.

Полный контейнерный запуск по-прежнему доступен через `docker compose up --build`;
в нём Vite обращается к `backend:8000`, а миграции применяются при старте API.
Для демонстрационного контента используйте seed по инструкции backend.

После регистрации Дядя Дебаг представит кампус. Двигайтесь стрелками или WASD,
взаимодействуйте клавишей `E`; открывайте телефон кнопкой или `Tab`, закрывайте
`Escape`. В каждом из корпусов Backend, Frontend и Analytics поговорите с наставником:
он предлагает две мини-игры. Примите интересное дело, подойдите к станции справа
и нажмите E. Можно принять несколько дел и переключать их на станции. После
проверки результата вернитесь к NPC, обсудите работу и сохраните впечатление.
Профиль, результаты, этапы и достижения доступны в CampusOS.
Для демонстрационного контента после миграций выполните команды seed из README
backend. CampusOS предоставляет журнал, карту, контакты, профиль, отчёт,
достижения, справку и выход. Отчёт новых мини-игр учитывает впечатления, исследование и время участия;
правильность и использование помощи не определяют интерес к профессии.

Игровые PNG находятся в `public/content/` и доступны Phaser/React по URL
`/content/...`. `src/world.ts` хранит только визуальный manifest трёх корпусов;
опубликованное неизвестное направлению остаётся доступным в текстовом fallback.

Для остановки используйте `docker compose down`. Команда `docker compose down -v` удаляет локальные данные базы.

## Итоговый отчёт и администрирование этапа 7

Исторический экран «Результаты» показывает сохранённые сервером факты InterestEvent,
объяснимые направления для дальнейшего изучения, следующий шаг и достижения.
Он не является психологической диагностикой. Пользователь с ролью `admin`
видит раздел «Администрирование»: там можно создавать, редактировать, удалять,
публиковать и снимать с публикации сценарии и `choice`-задания. Сервер
отклоняет изменение опубликованного или уже использованного контента.

## Проверки

```sh
npm ci
npm run lint
npm run typecheck
npm test
npm run build
```

Проверки backend и миграции описаны в соседнем репозитории. Секрет `JWT_SECRET` в `.env.example` предназначен только для локальной разработки; измените его в `.env` перед запуском.
Токен входа хранится в `localStorage`; после перезагрузки клиент проверяет его через `/auth/me`. Направления, прогресс, профиль и рекомендации каждый раз читаются с backend, поэтому браузер не является источником результатов. При ответе 401 сессия завершается.


## Интерактивные ситуации

| Направление | Мини-игра | Основное действие |
|---|---|---|
| Backend | Пятничный релиз | Мониторинг, живые логи, локализация, исправление, smoke-проверка |
| Backend | Очень маленькая фича | Написание Python, документация, подсказки, реальные проверки логики |
| Frontend | На моём мониторе нормально | Выбор элементов, правки свойств, проверка трёх размеров |
| Frontend | Пользователь ничего не понимает | Работающий прототип формы, пять улучшений, прогон пользователя |
| Analytics | Заказчик хочет кнопку | Интервью, заметки, предложение процесса, критерии приёмки |
| Analytics | Почему всё стало лучше? | Срезы dashboard, карточки операций, фильтрация, сравнение |

`Dialogue.tsx` — прежний компонент диалога, вынесенный из App и расширенный
сценами. Другой системы NPC-диалогов нет. `campusos/QuestInteraction.tsx`
связывает общую станцию и диалоги с авторитетным API, панели игр находятся в
`campusos/games/`. Общие стили панелей, инспектора, редактора, таблиц, обратной
связи и устройств находятся в `style.css`. Новые зависимости не добавлены.

Все значимые действия сохраняются на сервере, запросы повторяются с тем же UUID
при неопределённой доставке. Редакторы автоматически сохраняют черновики;
проверки ожидают отправки изменений. Незавершённый ввод перед немедленным
закрытием временно хранится локально с ключом игрока и задания; после
синхронизации используется серверное состояние. Учебный Python поддерживает ограниченное
подмножество языка; подсказки помощника заранее подготовлены и не требуют
внешнего AI API. Просмотр примера и его использование учитываются отдельно.

Ориентир 5–10 минут — цель игрового дизайна; время первого прохождения необходимо
измерить на новых игроках. Искусственной задержки или таймера допуска к финишу нет.

Запуск: телефон → «Задачи» → доступное дело → «Начать задание» → наставник
→ рабочая станция → наставник → впечатление. Открытие карточки только
показывает её; отслеживание выбирает уже принятое дело. Вступление и
обсуждение восстанавливаются после закрытия. Пробел продолжает линейную
реплику, выбор ответа требует отдельного действия; Esc позволяет вернуться позже.

Диагностика использует вкладки, отдельные поток/паузу/автоследование и
закреплённые детали лога. Макет редактируется числовыми полями и ползунками;
прототип — свободными подписями и настройкой полей. Режим использования
формы отделён от её редактирования. Пошаговый виртуальный пользователь
меняет реальные поля прототипа и останавливается на первом затруднении. Необязательные проверки доступны
внутри инструментов и не отменяют основной результат.

### Живые диалоги и казуальные инструменты

У каждого дела есть выбор «помочь / потом». Временный отказ сохраняет короткое
напоминание у NPC. «Отказаться» в телефоне сбрасывает текущий проход: после
повторного старта показывается полное вступление. История событий сохраняется.
Space и Enter продолжают обычную реплику; цифры выбирают ответ, Esc закрывает
разговор. Ответ об интересе завершается реакцией наставника.

В терминале функции работает локальный чат-помощник с постепенным выводом
подсказки. Он не отправляет вопросы внешним AI-сервисам. Интервью с заказчиком
представлено перепиской с 13 вопросами и конструктором решения. Расследование
данных открывает зацепки постепенно. Регистрация исправляется нажатием на пять
элементов формы с немедленным предпросмотром и проверкой виртуальным пользователем.

### Полировка интерфейсов заданий

Окна мини-игр разделены на заголовок, рабочую область и постоянную строку
состояния. Прокручивается только рабочая область; сообщения не уезжают за экран.
Приветствие наставника предлагает ответ игрока, финальная реакция зависит от
дела и интереса. В AI-чате выбираются 13 подготовленных вопросов, произвольного
ввода нет. Неверное решение в интервью обсуждает клиент в диалоге, после чего
можно вернуться к переписке.
