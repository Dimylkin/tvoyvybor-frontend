# ТвойВыбор.exe — frontend и локальный запуск

Этот репозиторий содержит React/TypeScript приложение и Docker Compose. Phaser отвечает за кампус и игровые взаимодействия, React — за CampusOS и диалоги, backend хранит авторитетное состояние квестов.

## Запуск

Положите репозитории рядом в одной директории:

```text
Code/
├── tvoyvybor-backend/
└── tvoyvybor-frontend/
```

Нужны Docker Compose, Node.js (22 или новее) и Python 3.12 или новее.
Для нового окружения создайте `.env` из `.env.example` и замените JWT-секрет.
Если `.env` уже существует, сохраните его. Значения PostgreSQL и JWT должны
совпадать с настройками backend; пароль в URL должен быть URL-кодирован.
Из каталога frontend:

```sh
cp .env.example .env  # только если .env ещё нет
npm ci
docker compose up -d db
```

PostgreSQL доступен только на `127.0.0.1:5433`; его данные сохраняются в
Compose volume `postgres_data`. Порт 5432 на хосте не используется. Для
существующего стенда используйте тот же Compose project (например, добавьте
`-p open-world-campus-ui-fixes-local` ко всем командам Compose), иначе будет
создан другой volume. При первом запуске новой базы примените миграции по
инструкции backend. Значения POSTGRES_* при повторном запуске не меняют уже
инициализированную базу.

В отдельных терминалах запустите приложения:

```sh
cd ../tvoyvybor-backend && make dev-start
# в другом терминале, из tvoyvybor-frontend:
make dev-start
```

Игра: <http://127.0.0.1:5173>, API: <http://127.0.0.1:8000/docs>,
проверка БД: <http://127.0.0.1:8000/health>. Vite проксирует `/api` на
локальный backend; при необходимости адрес прокси задаётся переменной процесса
`VITE_BACKEND_PROXY`. Каждый процесс останавливается через Ctrl+C, база —
`docker compose stop db` с тем же именем проекта. Данные сохраняются.
Если порт занят, остановите только принадлежащий вам процесс; при ошибке 503
проверьте контейнер, URL и учётные данные базы. Если зависимости отсутствуют,
повторите `npm ci` или настройку backend из его README.

Полный контейнерный запуск по-прежнему доступен через `docker compose up --build`;
в нём Vite обращается к `backend:8000`, а миграции применяются при старте API.
Для демонстрационного контента используйте seed по инструкции backend.

После регистрации Дядя Дебаг представит кампус. Двигайтесь стрелками или WASD,
взаимодействуйте клавишей `E`; открывайте телефон кнопкой или `Tab`, закрывайте
`Escape`. В корпусе Backend поговорите с Борисом и примите «Сервер ушёл в отпуск».
Осмотрите сервер, изучите терминал, настройте порт по журналу, запустите проверку
и доложите Борису. Прогресс, отслеживание и история сохраняются на сервере.
Для демонстрационного контента после миграций выполните команды seed из README
backend. CampusOS предоставляет журнал, карту, контакты, профиль, отчёт,
достижения, справку и выход. Отчёт содержит исторические данные старых квизов;
они не являются оценкой интереса по новым квестам.

Игровые PNG находятся в `public/content/` и доступны Phaser/React по URL
`/content/...`. `src/world.ts` хранит только визуальный manifest трёх корпусов;
опубликованное неизвестное направлению остаётся доступным в текстовом fallback.

Для остановки используйте `docker compose down`. Команда `docker compose down -v` удаляет локальные данные базы.

## Итоговый отчёт и администрирование этапа 7

Исторический экран «Результаты» показывает сохранённые сервером факты InterestEvent,
объяснимые направления для дальнейшего изучения, следующий шаг и достижения.
Он не является психологической диагностикой. Пользователь с ролью `admin`
видит раздел «Администрирование»: там можно создавать, редактировать, удалять,
публиковать и снимать с публикации сценарии и `choice`-задания. Сервер
отклоняет изменение опубликованного или уже использованного контента.

## Проверки

```sh
npm ci
npm run lint
npm run typecheck
npm test
npm run build
```

Проверки backend и миграции описаны в соседнем репозитории. Секрет `JWT_SECRET` в `.env.example` предназначен только для локальной разработки; измените его в `.env` перед запуском.
Токен входа хранится в `localStorage`; после перезагрузки клиент проверяет его через `/auth/me`. Направления, прогресс, профиль и рекомендации каждый раз читаются с backend, поэтому браузер не является источником результатов. При ответе 401 сессия завершается.
